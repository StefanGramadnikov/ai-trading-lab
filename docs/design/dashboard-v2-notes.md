# Dashboard design, iteration 2

File: `docs/design/dashboard-v2.html` (open by double-click; no network requests; all numbers, errors and times are SAMPLE DATA and labelled so). Built from v1; not visually checked in a browser by the designer role (no commands allowed), so the owner's look may still surface layout bugs.

Mock controls (dashed box, top): "Preview state" switches the whole dashboard into any state (new: close race, errors present, AI strategy stopped, AI budget at 83%). "Saving a change" makes the on/off save succeed, fail with "database does not answer", or fail with "session expired". "Sign out" shows the sign-in screen (any password works except the word `wrong`).

## Changelog against v1
1. **Switches work from the page** (mock of a real write path). Whole page now sits behind a sign-in screen; header shows "Signed in as owner" and Sign out. Confirm dialog keeps the wind-down wording and the required reason, and now says the change is saved with who, when and why. Saving shows "Saving...", then either a success message naming the audit entry (who, time, reason) with a View button to the audit trail, or a failure inside the dialog ("Could not save: the database did not answer. Nothing was changed ... nothing was written to the audit trail") with Try again. Session expired is a third outcome with "Sign in again".
2. **Verdict** says "Too early to tell" (plus a pill) when the run is under 3 days old or the lead of the first strategy over the runner-up is under 1 EUR; it still lists the standings after fees. The hint under the verdict explains the rule. New preview state "close race".
3. **Alert policy shown.** New System panel "What alerts you" (rules R1 to R5 with thresholds, "Right now" firing/quiet, how alerts behave, and a list of page-only items). Every item in "Needs your attention" now carries a tag: "Would send an alert (rule Rn)" or "Page only, no alert". Gallery cards state their alert status.
4. **AI pause explained.** AI page opens with "Is the AI allowed to ask right now?" listing the two pause causes. Breaker: count of failed calls, "Resumes in about 6 h (about 16:05 UTC), when the oldest of the 5 failed calls is 24 h old", and a table of the failed calls with how much longer each counts. Budget: meter with an 80% tick, amber at 80% and red at 100%, text state ("83% used: warning"), a banner, an attention item, an AI state in the Overview status strip. At 100% the page says it does not resume by itself. Strategy card, banners and gallery use the same wording.
5. **New view "Errors"** (own tab, count badge when unacknowledged errors exist): grouped by fingerprint, component, strategy, pair, count, first and last seen, status (New / Seen / Acknowledged), plain headline, alert line (sent or not), expandable detail (sanitized message and stack trace, both marked "secrets redacted", where, cycle id, decision id, fingerprint), Acknowledge button, filters by component and status, empty state. Overview gets an attention item and an "Errors to review" cell in the status strip. Preview state "Errors present" (4 sample errors: Kraken timeout recovered, database connection reset acknowledged, unexpected ValueError in the AI strategy with traceback, a paper broker invariant error).
6. Also added: "AI strategy stopped working" state (cycle fails repeatedly, rule R2); Overview status strip gets AI and Errors cells; the limits table shows the 80% heads-up and the exact breaker rule; navigation has six items (phone bottom bar gets tighter).

## Elements, data needed, and whether it exists today

| Element | Data needed | Exists today? |
|---|---|---|
| Sign-in screen, signed-in indicator, sign out | A single owner credential (password hash in the environment), session cookie, CSRF protection, attempt throttling | NEW work |
| Working on/off switch | A write endpoint that calls the same function as the CLI, with the signed-in name as `who` and the reason | The function and `live_strategy_audit` EXIST; the HTTP write path, auth and "who = dashboard:owner" are NEW |
| Save failure messages | The endpoint must return distinct errors (database unreachable, session expired, validation) and write nothing on failure | NEW (small) |
| "Too early to tell" verdict | Equity per strategy, run start; thresholds 72 h and 1 EUR | Derived from existing data; threshold constants are a decision (see questions) |
| "What alerts you" panel and per-item alert tag | The five rules as one shared definition used by both the page and the future Telegram sender (so they cannot disagree); current state per rule | NEW work: one rules module. Inputs mostly exist (loop age, per-pair data age, risk state, budget, breaker count) |
| Strategy "stopped working" (R2) | Per strategy: time of last equity point, last decision, consecutive failed cycles | Equity points and decisions EXIST; "consecutive failed cycles per strategy" is NEW (today strategy exceptions are only counted by type name in the cycle report, not stored per strategy) |
| Kraken down (R3) | Per-pair newest data age | EXISTS (needs a read query) |
| AI provider down (R4) | Consecutive unknown outcomes; unknown-outcome timestamps in the last 24 h | Unknown outcomes are charged and recorded in the budget flow ledger/decision detail; a query returning their timestamps is NEW (small) |
| Breaker resume time | Timestamps of the unknown calls, rule "stops at 5 in 24 h, resumes when the oldest is more than 24 h old" | Rule stated by the owner; code must be confirmed to use exactly this rolling window (v1 question 5, still to verify). Computation is NEW (small) |
| 80% budget warning and meter | Spend and cap | Spend EXISTS; the 80% warning level is NEW (a constant plus the attention item; a one-time alert at crossing needs "already alerted" state) |
| AI "Is it allowed to ask" card | Breaker state, budget state | Derived from the above |
| Errors view (all of it) | An **error journal** table: fingerprint (error type plus code location), component, strategy id, pair, first_seen, last_seen, count, status (new/seen/acknowledged), acknowledged_by/at, headline text, sanitized message, sanitized stack trace, last cycle id, last decision id, expected/unexpected flag, recovered flag | **Does NOT exist; new work.** Today strategy exceptions are only counted by type name in the cycle report. Needs: capture at every component boundary, a redaction step before storage, a fingerprint function, plain-language headlines (a lookup table per known error type; unknown types get a generic headline plus the type name), cycle and decision ids written into logs so the "find it in the logs" line works |
| Acknowledge button, Seen status | Write path on the journal with who and when; "Seen" set when the owner opens the detail | NEW (same auth as switches). Open question: opening marking "Seen" is a write on view; could instead be dropped |
| Errors badge, Overview attention item, "Errors to review" cell | Count of non-acknowledged fingerprints | Derived from the journal |
| Recurrence resets status to New | Journal logic | NEW |

## New open questions (max 3)
1. **Are the proposed alert thresholds right?** Proposed by me, not yet approved: nothing recorded for 40 min or 3 failed cycles in a row (R2); a price older than 45 min (R3); 3 unknown AI outcomes in a row or the breaker (R4); AI budget at 80% and 100% (R5); a repeat of the same error is not re-sent, and no repeat of any condition within 6 hours. Which would you change?
2. **What counts as "young" for the verdict?** I used under 3 days old or a lead under 1 EUR. With a 1 to 2 week run, do you want to wait longer (for example 5 days) before the page names a leader?
3. **Is one password plus the SSH tunnel enough for the switches?** The design assumes a single owner login, everything behind it, signed out by default after a period of inactivity (length to be decided). Do you also want sign-ins and sign-outs recorded in the audit trail?
